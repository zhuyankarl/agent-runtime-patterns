# 验证矩阵

按实际实现选择场景。此表是验收设计，不是已通过的测试记录；不能为填满表格运行真实外部副作用。优先使用隔离数据、测试端点、现有测试工具和可验证的模拟。

| 场景 | 应观察到的结果 |
|---|---|
| 空任务池 | 没有实际任务，不误报故障；是否调用模型符合成本要求 |
| 缺少必填字段、非法枚举、越界数值 | 应用程序拒收，目标数据不变，返回可定位原因 |
| 候选产物引用不存在对象或来源 | 规则要求核实时拒收或待复核，不假装校验成功 |
| 输出自洽但业务判断错误 | 质量样本能暴露错误；不把 schema 校验当成准确性评估 |
| dry-run 正常完成 | 返回独立的预演成功结果，无正式写入 |
| dry-run 下模型尝试应用 | 写入入口或权限拒绝，不能只靠提示词提醒 |
| 预演后产物被改 | 摘要不匹配，重新校验，不沿用旧回执 |
| 预演后目标被其他人改 | 检测版本冲突，保留他人修改，重算或报冲突 |
| 同一任务重复投递/运行 | 副作用不重复，返回已有回执或明确无操作 |
| 两个执行者同时领取/提交 | 符合任务并发契约，不靠“应该不会同时跑” |
| 租约到期但旧 worker 继续提交 | 过期所有者的写入被拒绝 |
| 批次中一条失败 | 明确整批原子回滚或逐条结果；不把部分成功标成全部成功 |
| 外部写入成功但响应丢失 | 标成未知并对账；不盲目重复发起副作用 |
| 写入后、完成记录前进程终止 | 从幂等回执/目标状态恢复，避免重复写入 |
| 模型进程退出码 0 但无有效产物 | 不报任务成功，保留原因和恢复位置 |
| 某项校验不可用或被跳过 | 标注未验证及影响，根据契约拒收或降级 |
| 达到重试上限 | 转入可见的失败/人工队列，不永久占住批次 |
| 遥测服务不可用 | 按契约降级；强审计要求不能静默绕过 |

## 报告格式

对每项实际执行的验证，记录：场景、输入/版本、执行方式、预期、实际结果、证据位置。未执行的场景单独注明原因。

证据强度由低到高区分为：文档声明、静态代码检查、隔离复现、端到端测试、部署环境验证。不要把静态检查报告成运行验证。

## 质量改进

若任务包含分类、摘要或方案判断，使用有代表性的固定样本覆盖常见项、边界项和已知错误。调整 prompt 或模型时比较质量、失败类型、成本和时延；不能只看“测试全通过”或模型自评分。

历史日志可供复盘，但未经评估、版本控制和发布授权，不应由 agent 自动修改生产规则。
